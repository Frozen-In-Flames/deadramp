# GAPS inventory — dedupe pass for the final batch (2026-10-31)

Method: every `- [ ] open` entry in GAPS.md (1,022 entries across 131 sections) was extracted verbatim and assigned to exactly one cluster by `gaps-batch/cluster.py` (ordered keyword/control-ID rules over the entry text; the full entry-to-cluster mapping is in `gaps-batch/inventory.json`, reproducible from `gaps-batch/entries.json`).

What a cluster means, stated plainly: a **family** is a shared engine *shape* — one design pattern that serves many groups (a workflow execution engine, an identity provider, a search indexer). Each instance still lands in its owning group’s own architecture and closes that group’s own entries; the family is where the batch designs once instead of 40 times. A **singleton** is a category-specific engine named in one group’s own taxonomy language — these do not dedupe across groups by design, and the batch works them per owning group. Nothing was merged by force: 888 distinct normalized entry texts underlie the 1,022 entries.

Result: **494 clusters** — 29 families covering 512 entries, and 465 singletons covering 510 entries.
